# Proof index and composition boundary

Durability scope: sync and acknowledged crash-survival claims below apply to the
default `"durability": "durable"` policy. With `"durability": "buffered"`,
receipts prove writes only; strict forwarding still checks those receipts. See
[audit durability policy](disk-logging.md#audit-durability-policy) for the exact
guarantees, receipt proofs, and remaining startup/rotation syncs.

The production proofs live beside executable Rust in `crates/gateway-core/src`.
Cargo compiles these sources into the gateway; Verus checks their contracts.
A specification function defines a property, an invariant describes valid states,
and executable function postconditions establish what a transition preserves or
changes. Most guarantees are established by these postconditions, not by a separate
file of named lemmas. Ghost histories are erased from the executable.

Read each `requires` clause before interpreting an `ensures` clause. Runtime code
in `gateway-runtime` is ordinary Rust and must supply valid states and truthful
external events. Checking the core does not mechanically verify those call sites.
The [end-to-end audit](end-to-end-audit.md) records tested bindings to network
and disk operations. Tests and proof mutations complement the contracts but do not enlarge
their formal scope.

## What has no theorem

There is no single theorem establishing that every byte reaching a provider has
an authorized tenant, correct credential, and durable audit record under every
thread interleaving and physical crash. The [end-to-end audit](end-to-end-audit.md)
traces that path step by step, enumerates every production effect site, and marks
each join as proved, tested, or assumed. The production body-write mediation chain is checked as described above; the remaining external boundaries include actual network effects, initial journal/file identity, physical syscall and storage-contract validation. The [security contract](security-contract.md)
and [storage contract](storage-crash-contract.md) specify those boundaries.

There is also no whole-process memory theorem. Logical slot/chunk bounds and a conditional sum bound for mapped streams are
verified; retained vector capacities, HTTP frame limits, queues, worker lifetimes,
and deadlines have runtime checks/tests. TLS/HTTP backing allocations, allocator
behavior, OS caches, and full resource-release composition remain outside that
proof. [Benchmarks](benchmarks.md) measure one workload rather than proving bounds.

Availability mode changes audit coverage after logging failure. Its authorization
path is the same runtime path as strict mode, but their complete noninterference
is not formally proved. Neither mode promises secrecy of arbitrary opaque body
contents, protection against a malicious approved provider, or exactly-once remote
execution. Origin confinement is not a resolved-IP-range/SSRF theorem.

## Verification trust and reproduction

The trusted computing base is listed in the
[security contract](security-contract.md#trusted-computing-base-and-evidence). The
production core introduces no `assume` or `external_body` escape; this does not
remove trusted specifications supplied by vstd.

Use the pinned toolchain and commands in the [README](../README.md). The
[mutation runner](../scripts/check_mutations.py) verifies the unmodified core
first, then checks deliberately broken variants. A mutant must fail a proof
obligation; syntax/type failures do not count as successful rejection. Mutants
confined to the bodies of distinct exec or proof functions are checked many to
a verifier run: Verus proves each function against the specifications of what
it calls, never their bodies, so such a mutant can be refuted only inside its
own function and cannot change any other function's result. The runner proves
the confinement for every batch by diffing the verifier's own intermediate
representation of the batch against the unmodified crate, and verifies any
mutant that fails that check, or that edits a specification, on its own.
[CI](../.github/workflows/ci.yml) also runs executable tests and proxy-policy tests.
Verification-check totals are not counts of independent security guarantees.

The [conditional shutdown argument](shutdown-proof.md) maps the verified drain
rank to worker ownership, shared-listener admission closure, cancellation, and
logger timeout. Eventual scheduling, finite synchronous calls/destructors, lock
progress, and timer behavior remain explicit assumptions; this is not a formal
verification of the thread scheduler or a hard wall-clock deadline.

## Log rotation

`log_rotation::RotatingStorage` implements the existing verified disk worker's
`Storage` contract over `SegmentIo`: successful writes extend the logical history
by exactly the offered bytes, rotation preserves earlier history and session,
indices advance one at a time, and successful sync covers that history. Its
size policy uses overflow-safe remaining-space comparisons and permits one intact
oversized frame per otherwise empty segment. Failure is permanent. Eight deliberate
rotation mutations guard the size/age policy, append, sync, index, creation
failure, and seal ordering/failure checks. Filesystem durability and mapping segments to logical history
remain explicit assumptions.

`session_recovery::SessionScanner::{next_record,recovered_prefix,recovered_to_end}`
composes the actual `recovery::Scanner` across files. The emitted sequence is the
exact ordered prefix of the recoverable records; every crossed segment has a
matching checked header and a complete tail. A cursor advances only by a decoded
record extent or from a sealed predecessor's clean end to byte 56 of its immediate
successor. The driver refreshes the predecessor after successor discovery to
close the EOF/rotation race. Eight deliberate mutations guard the handoff,
session checks, resume offsets, emission, and terminal errors. `Files` supplies
trusted path/metadata visibility. `snapshot::Snapshot` now proves
`Source` and `SeekSource` over primitive `FileRead` effects, including exact
accumulation, captured-length bounds, EOF classification, and seek/cursor updates.
See [recovery](recovery-proof.md#rotated-session-composition)
and [disk logging](disk-logging.md#automatic-rotation).

`RotatingStorage::writer_protocol` proves the production effect trace follows
`segment_protocol::run`. `creation_follows_seal` derives that each successor
creation attempt immediately follows a successful predecessor seal.
`no_append_to_predecessor` proves later appends target only the successor or later
segments, and `prefix` proves no event follows a failed effect. The trace is
supplied by the primitive effect contracts, not manually fabricated by the
caller. Durability/visibility of the named syscalls and file identities remain
trusted; their sequencing is checked. Snapshot tests and eight mutations check
the separate verified primitive-read binding. Naming, time sampling, CLI parsing,
and missing-file detection are not claimed as proved by this change.

## S3 shipping

| Claim | Contracts | External premise |
| --- | --- | --- |

| SigV4 authorization binds exact host, path, date, region, session token and payload hash | `s3::{canonical,scope,signing_key,string_to_sign,authorization,sign}` | AWS signature validation and SHA-256 security. |

| Date text is exactly the civil UTC timestamp, 16 bytes; unsupported years are rejected | `s3_delivery::{two,date_text,date}`; `calendar::civil` | The clock's supplied milliseconds. |

| Object path binds the batch identity and full payload hash | `s3::object_path` | S3 overwrite semantics; different batch boundaries can create overlapping objects. |
| S3 replies never poison the machine; non-acknowledgments preserve queue and counters | `shipping_driver::{Effects::send,deliver}` composed with `shipper::Machine::reply` | The verified S3 adapter supplies the reply policy. |

The runtime uses these executable functions. S3 introduces no new dependency,
external-body proof escape, or socket/file effect site. The runtime still
performs TLS, file operations, environment lookup, clock reads, and threading;
those operations and AWS itself are not verified by Verus. See the
[S3 destination guide](cloud-shipping.md#s3-destination) and the deliberate
mutation checks in `scripts/check_mutations.py`.

JSON response text is specified by `projection::{content_text,json_response_text}`: text blocks and message contents retain their order and separators, with top-level content taking precedence over output and choices. `json_row_text` composes depth-bounded JSON parsing, UTF-8 sanitization, text capping, and the raw fallback through the assistant row and `shipping_driver::projects` to enqueue. Provider field vocabulary remains an explicit protocol assumption.
